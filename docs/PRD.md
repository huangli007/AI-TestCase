## 2. 背景与目标

### 2.1 背景

测试用例是质量保障的核心资产,但当前存在明显痛点:

1. **编写成本高**:一份中等规模产品(5~8 个模块)的功能用例通常需要 1~3 人天手工编写,且依赖测试工程师个人经验,水平参差;
2. **资料形态多样**:测试输入往往不只是 PRD 文本,还包括 UI 原型图、交互设计稿、产品演示视频、接口文档等,人工阅读与转述这些素材耗时且易遗漏;
3. **覆盖面不足**:手工编写容易漏掉负向场景(非法输入、越权、并发)、边界值(库存临界、金额精度)、兼容性与安全场景;
4. **缺乏统一格式**:不同团队的用例模板、优先级定义、字段规范不一致,难以沉淀复用。

### 2.2 目标

构建一个 **自动生成测试用例的 Agent**:

- **多模态输入**:支持文本(txt/md/docx/pdf/csv)、图片(UI 截图/原型/设计稿)、视频(产品演示/录屏)作为输入素材;
- **自动测试点分析**:由大模型理解素材,输出结构化产品分析(功能清单、业务流程、风险点)与测试点清单;
- **高质量用例生成**:基于黑盒测试方法论(等价类、边界值、场景法、错误推测、状态迁移),生成字段完整、步骤可操作、预期可验证的测试用例;
- **质量评审闭环**:生成后自动做一轮质量门禁评审,补漏、去重、修正;
- **算力可外接**:支持对接任意 OpenAI 兼容的大模型 API(DeepSeek / Qwen 通义 / OpenAI / 智谱 / Kimi 等),由用户自备 Key,灵活选择模型(含视觉模型);
- **结果可交付**:一键导出 Excel / Markdown / JSON,直接进入用例管理流程。

### 2.3 成功指标

| 指标 | 目标值 | 衡量方式 |
|------|--------|---------|
| 用例编写效率提升 | 单产品用例产出 ≤ 30 分钟 | 端到端耗时统计 |
| 用例可执行率 | ≥ 95%(步骤、预期完整可执行) | 抽样人工评审 |
| 负向/边界场景占比 | ≥ 30% | 导出数据统计 |
| 用例格式规范率 | 100% 字段完整 | 模型校验通过率 |
| 模型可替换性 | 支持 ≥ 3 家主流 API | 配置切换验证 |

### 4.2 功能详情

#### 4.2.1 多模态输入解析

**需求描述:**
用户可传入任意数量的文本/图片/视频文件,系统自动识别类型并解析为统一文本素材。

**交互流程:**
1. 用户在桌面 GUI 中选择/拖入文件(Windows/macOS 均可),或 CLI 指定文件路径;
2. 系统按扩展名分类:文本 -> 直接提取;图片 -> 压缩后交视觉模型;视频 -> ffmpeg 抽帧(均匀采样,默认 ≤12 帧)后交视觉模型;
3. 输出解析报告:成功解析文件、跳过文件、失败原因列表。

**规则:**
| 元素 | 类型 | 说明 | 规则 |
|------|------|------|------|
| 文本扩展名 | txt/md/markdown/csv/json/log/yaml/html | 直接读取 | 编码容错(utf-8 errors=replace) |
| 文档扩展名 | docx/pdf | python-docx / pypdf 提取 | pdf 扫描件提示改用图片 |
| 图片扩展名 | png/jpg/jpeg/webp/bmp/gif/tiff | 视觉模型理解 | 最长边压缩到 1280,JPEG 编码 |
| 视频扩展名 | mp4/mov/avi/mkv/webm/flv/wmv/m4v | 抽帧 + 视觉模型 | 每视频 ≤12 帧,间隔可配 |

**异常处理:**
- 单文件解析失败:记录错误,不中断整体流程;
- 所有素材均失败:报错终止,列出原因;
- 图片/视频但模型不支持视觉:给出明确提示,建议配置 vision_model。

#### 4.2.2 产品分析与测试点梳理(阶段一)

**需求描述:**
LLM 基于素材输出结构化产品分析 JSON,字段与数据模型严格对应。

**输出结构:**
```json
{
  "product_name": "产品名称",
  "product_type": "Web应用|移动App|小程序|桌面应用|接口服务|硬件/嵌入式|其他",
  "target_users": "目标用户",
  "core_value": "核心价值",
  "modules": [{"module": "模块", "feature": "功能点", "rules": ["业务规则"]}],
  "business_flows": [{"name": "流程", "description": "描述"}],
  "risk_points": ["风险点"],
  "test_points": [{"id": "TP-001", "module": "模块", "name": "测试点", "type": "功能|UI|兼容性|安全性|性能|易用性|接口|数据", "description": "描述", "priority": "P0|P1|P2|P3", "inferred": false}]
}
```

**约束:**
- 测试点覆盖:正常流程、边界值、异常输入、权限、并发、兼容、安全、性能、数据一致性;
- 每个主要模块 ≥ 2 个测试点,总量 8~20 个;
- 资料缺失部分基于行业常识推断,`inferred=true` 标注。

#### 4.2.3 测试用例生成(阶段二)

**需求描述:**
为每个测试点生成 2~4 条用例(至少 1 条正常 + 1 条异常/边界),总量上限可配置(默认 80)。

**用例字段:**
| 字段 | 说明 | 要求 |
|------|------|------|
| case_id | 用例编号 | TC-001 起,全局唯一,自动归一化 |
| module | 所属模块 | 与测试点一致 |
| test_point | 对应测试点 | |
| title | 用例标题 | 简洁可执行 |
| priority | 优先级 | P0 核心流程 / P1 重要 / P2 次要 / P3 边缘 |
| case_type | 用例类型 | 功能/UI/兼容/安全/性能/易用/接口/数据/异常 |
| precondition | 前置条件 | 无则填"无" |
| test_data | 测试数据 | 具体数据,无则填"不适用" |
| steps | 操作步骤 | 具体到按钮/输入,禁止模糊 |
| expected | 预期结果 | 可验证,禁止"正常""无误" |

**质量守则(注入 Prompt):**
- 负向用例必查:非法输入、越权、重复提交、并发、空数据、超长数据;
- 优先级规则:P0 阻断性主流程 > P1 重要功能 > P2 次要/异常 > P3 边缘。

#### 4.2.4 质量评审(阶段三)

**需求描述:**
以产品分析为基准评审用例集:补漏、去重、修正模糊/不可验证用例、校正优先级,输出修正后的完整用例集与评审报告。

**评审报告:**
- summary:1~3 句评审总结;
- gaps:补充的遗漏点;
- issues:修正的问题;
- cases:修正后完整用例集(重新编号)。

**开关:** 配置 `review_enabled`(默认 true),CLI 可 `--no-review` 关闭。

#### 4.2.5 大模型 API 接入

**需求描述:**
支持任意 OpenAI 兼容 Chat Completions 接口,文本模型与视觉模型可分离配置。

**配置项(config.yaml / 环境变量):**
| 配置 | 环境变量 | 说明 |
|------|---------|------|
| llm.base_url | LLM_BASE_URL | API 地址,默认 DeepSeek |
| llm.api_key | LLM_API_KEY | 密钥 |
| llm.model | LLM_MODEL | 文本模型 |
| llm.vision_model | LLM_VISION_MODEL | 视觉模型,如 gpt-4o/qwen-vl-max |
| llm.temperature | - | 默认 0.6 |
| llm.max_retries | - | 默认 3,指数退避 |
| pipeline.mock_mode | - | true 时走 Mock,免 Key 演示 |

**能力:**
- JSON 结构化输出强制(`response_format: json_object`)+ 容错解析(代码块剥离、截断修复);
- 失败自动重试(指数退避);
- Mock 客户端:离线返回高质量示例,用于演示/CI。

#### 4.2.6 导出

**Excel(主交付物):**
- Sheet1 产品分析、Sheet2 测试点清单、Sheet3 测试用例(核心)、Sheet4 评审报告;
- 优先级 P0~P3 颜色标识,冻结首行,自动换行。

**Markdown:** 产品摘要 + 测试点表 + 用例表 + 评审说明。

**JSON:** 完整结构化产物(analysis/review/cases + 时间戳)。

#### 4.2.7 交互入口

**跨平台桌面 GUI(主交付形态,Qt/PySide6,支持 Windows/macOS):**
- 窗口布局:左侧素材区(添加/移除文本、图片、视频文件)+ 右侧配置区(模型参数)+ 底部运行/导出区;
- 功能:文件多选与拖拽添加、模型配置(API/模型/温度/评审开关)、一键运行、阶段进度展示、结果预览(产品分析/测试点/用例表格)、一键导出 xlsx/md/json;
- 跨平台架构:核心逻辑与 UI 解耦,平台差异(路径、字体、文件选择、打开目录)通过 Qt 标准能力与适配层收敛,同一套代码在 Windows/macOS 上运行;
- 支持保存/加载配置,API Key 本地保存(可选加密),不依赖浏览器。

**CLI(辅助,自动化/CI 场景):**
```bash
# 真实模式(需配置 API Key)
python main.py --files prd.pdf prototype.png demo.mp4 --out output/ --config config.yaml

# 离线演示模式
python main.py --files samples/sample_prd.md --out output/ --mock

# 跳过评审
python main.py --files ... --no-review
```

## 5. 非功能需求

### 5.1 性能需求
- 单个文件解析:文本 < 1s,单图分析 < 10s,视频抽帧 < 30s(10 分钟视频);
- 全流程(10 个测试点规模):≤ 5 分钟(取决于 API 响应);
- 视频抽帧:单视频 ≤ 12 帧,避免超长视频造成 token 爆炸。

### 5.2 安全需求
- API Key 不落日志,支持环境变量注入;
- 敏感信息(手机号/地址)在用例中按要求脱敏展示;
- 不将素材上传至非用户指定第三方(仅调用用户配置的 API)。

### 5.3 兼容性需求
- 桌面 GUI:跨平台架构,支持 Windows 10/11 与 macOS 12+ 双平台;CLI 核心库亦跨平台,Python ≥ 3.10;
- 平台差异收敛:路径处理统一使用 pathlib,文件对话框/打开目录使用 Qt 标准组件(QFileDialog/QDesktopServices),中文字体自动适配系统(Windows 微软雅黑 / macOS PingFang SC);
- ffmpeg:使用 imageio-ffmpeg 自带二进制,Windows/macOS 免系统安装;
- API 兼容:OpenAI 协议即可接入,不绑定厂商。

### 5.4 可维护性需求
- 模块化:parsers / llm / pipeline / exporters 解耦,可单点替换;
- 数据模型(pydantic)约束各阶段输出,失败可快速定位;
- 配置驱动,无需改代码切换模型与参数。

## 8. 风险评估

| 风险类型 | 风险描述 | 影响程度 | 应对措施 |

| 技术风险 | LLM 输出格式不稳定 | 中 | 强制 json_object + 容错解析 + 重试 |
| 业务风险 | 生成用例质量依赖模型能力 | 中 | 评审阶段补漏 + 高质量 Prompt 工程 |
| 业务风险 | 无需求文档时推断不准 | 低 | inferred 标记,提醒人工确认 |
| 资源风险 | 依赖用户自备 API Key | 低 | Mock 模式可离线演示,不阻塞体验 |
